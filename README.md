# WorkTimeTracker

יישום מקומי ל-Windows 10/11 למעקב אחר חלונות וזמני עבודה. המידע נשאר במחשב;
היישום אינו שולח נתונים לרשת ואינו שומר תוכן הקלדה, לוח גזירים או צילומי מסך.

## בנייה והפעלה

נדרשים Windows ו-.NET 8 SDK:

```powershell
dotnet build .\WorkTimeTracker.sln
dotnet test .\WorkTimeTracker.sln
dotnet run --project .\WorkTimeTracker.App\WorkTimeTracker.App.csproj
```

לפרסום קובץ הפעלה עצמאי ל-Windows x64:

```powershell
dotnet publish .\WorkTimeTracker.App\WorkTimeTracker.App.csproj -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
```

הקובץ נוצר בתיקיית `publish` שמתחת לתיקיית הפלט של הפרויקט. להפעלה ישירות
ברקע ניתן להוסיף `--minimized`; גם ההפעלה עם Windows משתמשת באפשרות זו.
סגירת החלון או מזעורו מסתירים אותו, והמעקב ממשיך. לחיצה כפולה על סמל אזור
ההודעות פותחת את לוח הבקרה. תפריט הסמל מאפשר להתחיל או לסיים יום, להשהות
או לחדש מעקב, לפתוח הגדרות ולצאת. Windows קובע אם הסמל מופיע באזור הסמלים
המוסתרים. כדי לסיים את התהליך ולשמור את הנתונים יש לבחור **יציאה** בתפריט.

## מידע והגדרות

מסד SQLite, קובץ ההגדרות ויומן השגיאות נמצאים בתיקייה
`%LocalAppData%\WorkTimeTracker\`. הזמנים נשמרים ב-UTC ומוצגים בזמן המקומי.
נתוני החלונות, האינטראקציות ואירועי המערכת נשמרים כאותות גולמיים, כך ששינוי
ספי החישוב חל גם על דוחות קודמים. ברירת המחדל היא שמירת נתונים ללא הגבלת זמן;
ניתן לשנות את תקופת השמירה או להחריג יישומים בהגדרות.

**זמן מוצג** נספר כאשר המשתמש נוכח, החלון גלוי מעל הסף, והוא בחזית או
שהייתה בו אינטראקציה לאחרונה. כמה חלונות עשויים להיות מוצגים בו-זמנית ולכן
סכומם יכול לעלות על אורך היום. **זמן עבודה בפועל** נספר לחלון שבחזית כאשר
הייתה קלט מקלדת או עכבר לאחרונה; לכל היותר חלון אחד פעיל בכל רגע.
פער קצר מסף הפעילות או הנוכחות נספר בין שני אירועי קלט. לאחר שמתברר
שהפער הגיע לסף, הדוח נחתך בדיעבד בשניית הקלט האחרונה במקום להוסיף
את זמן החסד; פער שעדיין קצר מהסף עשוי להופיע זמנית עד שיתברר אורכו.
הספים ניתנים לשינוי בהגדרות. יום שגולש לחצות משויך לתאריך תחילתו; נעילה
ממושכת יכולה לסיים אותו בדיעבד בזמן הנעילה.

גם היעדר קלט רצוף במשך סף הסיום האוטומטי סוגר יום פתוח בזמן הקלט האחרון.
הבדיקה מתחילה מקלט שנצפה לאחר הפעלת הגרסה החדשה; היא אינה משנה ימים
שכבר נסגרו ואינה מסיקה חוסר פעילות מזמן שבו היישום לא פעל או המעקב הושהה.
קלט חדש לאחר סיום אוטומטי פותח יום עבודה חדש.

בלוח הבקרה ניתן לבחור תקופה ולייצא ל-Excel או ל-CSV בקידוד UTF-8 עם BOM.
הנתונים כוללים שמות יישומים וכותרות חלונות, ולכן כדאי להגן על התיקייה
וקובצי הייצוא בהתאם לרגישותם.

כאשר החלון גלוי והתקופה כוללת את היום, הדוח מתעדכן כל חמש שניות וכולל
תצפיות שטרם נשמרו. המקטע הנוכחי זמני עד לדגימה הבאה ועשוי להשתנות בדיעבד.
כאשר החלון מוסתר אין רענון של לוח הבקרה והמעקב ממשיך ברקע.

בתצוגה היומית אפשר לערוך את גבולות יום העבודה באמצעות סמל העיפרון. גבולות
ערוכים משמשים בדוחות ובייצוא, והגבולות המקוריים מוצגים בהצבעה על "נערך ידנית".
אין לאפשר חפיפה ליום אחר. ביום פתוח ניתן להקדים את ההתחלה בלבד; לאחר סגירתו
אפשר לערוך גם את הסיום ולהזיז את ההתחלה קדימה.

ניתן להגדיר בהגדרות כללי תוויות לפי יישום באמצעות ביטויי regex עם קבוצה בשם `label`, ולבדוק אותם מול כותרות אחרונות שנשמרו במאגר המקומי. התוויות מחושבות מתוך הכותרות המקוריות בזמן הפקת הדוח, כך ששינוי כלל מעדכן גם תקופות קודמות. בלוח הבקרה אפשר לבחור קיבוץ לפי יישום → תווית → כותרת, תווית בלבד או יישום בלבד; הייצוא משתמש בקיבוץ הנבחר.

ניתן גם להגדיר כללי נרמול לכותרות ולבדוק אותם מול כותרות אחרונות. הכללים
מופעלים בזמן הפקת הדוח, לפני חילוץ התווית והקיבוץ; הכותרת המקורית נשמרת ללא שינוי.

לאחר הפסקת חשמל מזוהה זמן כיבוי המחשב בנפרד מזמן ללא מעקב. אם הכיבוי נמשך
לפחות כמו סף הסיום האוטומטי, המקטע הקודם נסגר בפעילות האחרונה ונפתח מקטע
חדש בזמן האתחול. ייתכנו כמה מקטעי עבודה באותו תאריך והם מוצגים בנפרד ומסוכמים בדוח.

## מגבלות מוכרות

- חלונות של תהליכים מורמים (Administrator) או מוגנים, שאין גישה לנתיב
  הקובץ שלהם, נרשמים כיישום **"Unknown (elevated)"** עם כותרת החלון.
  כאשר WorkTimeTracker אינו רץ כמנהל, Windows (UIPI) עשוי שלא להעביר אליו
  קלט שמיועד לחלונות כאלה, ולכן הזמן הפעיל בהם עשוי להימדד בחסר.
  חלונות בעלי שקיפות לפי פיקסל אינם נמדדים במדויק.
- משחקים במסך מלא בלעדי, שולחן עבודה מאובטח וחיבור שולחן עבודה מרוחק
  עלולים שלא להימדד במדויק.
- מדידת נראות מבוססת על גבולות חלונות מלבניים ודגימה תקופתית; שינויים בין
  דגימות ואירועים בזמן קריסה אינם ניתנים לשחזור מלא. אותות בתדירות גבוהה
  נכתבים למסד כל 5 שניות, ולכן קריסה עלולה לאבד עד כ-5 שניות אחרונות.
- צריכת משאבים במחשב הפיתוח, במצב יציב (לאחר 2 דקות מההפעלה הממוזערת):
  כ-0.8%–1.4% מליבת מעבד אחת (ממוצע כ-1%, תלוי בעומס ובכמות הקלט), כ-100 MB
  Working Set וכ-36 MB זיכרון פרטי. בדקות הראשונות לאחר ההפעלה הצריכה גבוהה
  יותר בגלל הידור JIT. העלות הנותרת נובעת בעיקר מ-hooks הקלט הגלובליים, שכל
  הקשה או תזוזת עכבר במערכת עוברת דרכם, ומהדגימה בכל שנייה. פתיחת הממשק
  וייצוא Excel עשויים להעלות את השימוש בזיכרון.
